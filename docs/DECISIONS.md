# Build decisions to review

The user was away during the first build, from 2026-10-29. These are the choices made without them. Each one can be changed. Newest last.

| # | Area | Decision | Why | Easy to change? |
|---|---|---|---|---|
| 1 | Process | "Astra agents" for review was read as independent reviewer subagents, because no tool or agent named Astra exists on this machine. | Nothing matched the name | Yes |
| 2 | GPUI | Pin `gpui-kit = "=0.8.1"` from crates.io (it brings `gpui-pre = "=0.3.10"`). Do not use the local `watzon/gpui-kit` fork. | The fork is on a feature branch; the published release is the stable base | Yes |
| 3 | GPUI | The selected-text menu uses GPUI Kit's cross-platform context menu, not the native macOS text menu that Kyllene uses. | The native menu needs an `unsafe` exception, which was approved for Kyllene only. The GPUI Kit menu also works on Windows | Yes |
| 4 | GPUI | The "progressive blur" at the top and bottom of the chat is a layered gradient fade from the canvas color to transparent. | GPUI has no blur filter for elements | Yes, if GPUI gains a blur |
| 5 | Repo | Product binary is `consort`. The desktop app binary is `consort-desktop`. | Matches the product name | Yes |
| 6 | Harness | Build the native Codex adapter (`codex app-server`) in this build, not later. | The Windows test machine has `codex` and `claude` but no Node.js, and the ACP adapters for Claude and Codex are npm packages | Yes |
| 7 | Tooling | Copy the repo to the Windows machine with a git bundle (`scripts/sync-bigboi.sh`). | Windows OpenSSH runs commands in `cmd.exe`, which breaks `git push` over ssh | Yes |
| 8 | Toolchain | Pin Rust 1.98.1 instead of 1.94.1, the same version as Kyllene. | `gpui-pre` 0.3.10 and `gpui-pre-macos` 0.3.10, which GPUI Kit 0.8.1 needs, use `std::hint::cold_path` and `Option::map_or_default`, which newer Rust stabilized | Yes |
| 9 | Proto | Keys, signatures and nonces travel as lowercase hex. A peer signs `consort-auth-v1\n<origin>\n<nonce hex>`. The origin is the normalized `scheme://host[:port]` of the hub URL. | Hex needs no extra crate. Both sides must sign the same bytes, and protocol.md did not say which | Before the first release only |
| 10 | Proto | `auth.response` is a request. The hub answers `ok` or `unauthorized`, and the peer sends `hello` after that. | The peer learns that authentication failed before it sends `hello` | Yes |
| 11 | Proto | Workers sign blob requests with `X-Consort-Worker`, `X-Consort-Timestamp` and `X-Consort-Signature` over `consort-http-v1\n<METHOD>\n<origin>\n<path>\n<timestamp>\n<worker id>`, with 5 minutes of clock skew. | protocol.md said "a signature header" with no format | Before the first release only |
| 12 | Proto | Pairing codes use the Crockford base32 alphabet. Typed codes ignore case, hyphens and spaces, and read `O` as `0` and `I`/`L` as `1`. | 32 characters give each random byte an equal chance, and typed codes forgive common mistakes | Yes |
| 13 | Proto | The `session.events` ack is the response body `{session_id, last_seq}`, not a separate `ack` message. Every hub command gets a response, and "None" results are `{}`. | One correlation rule (`re`) for every request | Yes |
| 14 | Proto | A harness question (`request.opened` with kind `question`) becomes a decision with a `request_id`. The hub sends the answer with `session.respond`. Approval `details` carries the approval `kind`, so the approval has no separate `kind` field. | A harness question has a question and options, like a decision. One `kind` field avoids two values that can disagree | Yes |
| 15 | Proto | Request options have a `kind`: `allow_once`, `allow_always`, `deny_once`, `deny_always` or `choice`. | The hub must know whether an answer allows or denies, to set the approval status | Yes |
| 16 | Proto | Added to the client API: `message.list` (paging), `repo.create`, `worker.set_paused`, `archived` on `channel.archive` and `task.archive`, and a client `hello` body. | Clients need history paging, a way to attach repos, the Pause item in the worker menu, and unarchive | Yes |
| 17 | Proto | Added fields: `channel_id` and `task_id` on `session.start`, `worker_id` on Task, `repo_ids` on Channel, `reactions` on Message, `paused` on Worker, `request_id` and `channel_id` on Approval, `request_id` on Decision, `auth_detail` on harness accounts. The feed also carries `repo`, `read_marker` and `client`. | `workspace.release` names a task, task cards show an offline worker, read markers must sync across clients, and the hub must map answers back to harness requests | Yes |
| 18 | Proto | Worker labels on the hub are the user's labels. Placement matches a label from that list or from the inventory (`worker.toml`). | `worker.set_labels` and `worker.toml` both set labels, and neither can overwrite the other | Yes |
| 19 | Proto | The client view of a Client has only `push_provider`. The push token stays on the hub. | Other clients do not need another device's token | Yes |
| 20 | Proto | The inventory `hash` is FNV-1a 64 over the inventory JSON with an empty hash, written as `fnv1a64:<16 hex>`. | It only detects changes, and proto has no crypto crate | Yes |
| 21 | Proto | A message from the Everything coordinator renders as `<everything_message id at>` in turn input. A suggestion from a channel coordinator has `from="chn_..."`. Decision free text goes inside `<decision_answered>`. | protocol.md listed these events but did not show them | Yes |
| 22 | Proto | `post_message` attachments are channel file paths, not blobs. | A model cannot upload a blob, but it can see channel files | Yes |
| 23 | Proto | Hub tool arguments take times as RFC 3339 strings. `Timestamp` reads Unix milliseconds or RFC 3339 and always writes milliseconds. | Models write dates more reliably than epoch numbers | Yes |
| 24 | Proto | Readers ignore unknown fields everywhere. No type uses `deny_unknown_fields`. An unknown error code reads as `unknown`. Empty optional fields serialize as `null`. | Forward compatibility between hub, worker and client versions | Yes |
| 25 | Proto | Tasks: Ready for review and Needs input are the "your turn" groups. Failed is on the Active tab but not in a "your turn" group. Only Review to Resolved is allowed for the user, so the user cannot resolve a Failed task. They retry or archive it. | This follows the data-model.md table as written | Yes |
| 26 | Proto | Transitions that the hub makes on its own (placement, session events, timers) use the actor `system`. `submit_for_review` and the turn end both allow `working` to `review`. | The table names causes, not actors. This maps each cause to the side that triggers it | Yes |
| 27 | Deps | Workspace deps: `serde 1.0.229`, `serde_json 1.0.154`, `uuid 1.29.0`, `thiserror 2.0.21` as caret versions, and `schemars =1.2.3` as an exact pin. | The first four are stable, and the lock file pins them. Tool schemas depend on schemars output, which can change in a minor release | Yes |
| 28 | Desktop | Bundle the static Atkinson Hyperlegible Next and Mono TTFs (Regular, Italic, Medium, SemiBold, Bold) from the upstream `googlefonts/atkinson-hyperlegible-next` and `-next-mono` repos, with the OFL text from google/fonts. | google/fonts holds only the variable fonts. GPUI picks weights reliably from static faces, as in Kyllene. The license is the same | Yes |
| 29 | Theme | The loader renames 7 mapping keys to their GPUI Kit 0.8.1 names (`link.foreground` to `link`, `drag_border` to `drag.border`, and so on) and derives the 41 kit keys that the mapping does not list (`button.*`, `*.hover`, `*.active`, `switch.thumb`, `table.foot.*`) with the same expressions. A test checks that every kit key has a value. | Without a value the kit falls back to its own palette, so a theme would leak non-Consort colors. `design/gpui-kit-mapping.json` was not edited | Yes |
| 30 | Theme | Each Consort theme registers twice with GPUI Kit, as `<Name> dark` and `<Name> light`. | The kit registry keys themes by name | Yes |
| 31 | Theme | Text size: Smaller is 0.9, Default 1.0 and Larger 1.12 of every type style, rounded to whole pixels, with line heights rounded to even pixels. | The design names the setting but not the steps | Yes |
| 32 | Theme | The user themes folder is `directories`' config dir plus `consort/themes` (on macOS `~/Library/Application Support/consort/themes`). Settings shows the real path. The folder is polled every 2 seconds, and a theme whose name is already loaded is rejected with a message. | Same rule as the client store. The Paper design showed `~/.config`. Polling needs no watcher dependency | Yes |
| 33 | Desktop | Every right-click menu and select uses one Consort menu layer: GPUI `anchored` with anchor switching, positioned from the middle of the trigger and padded by half its height, so it clears the trigger whichever way it flips. This replaces decision 3: GPUI Kit's context menu is not used. | GPUI Kit's `ContextMenu` snaps to the window edge instead of flipping (AGENTS.md rule 4), and one layer keeps menus and selects identical | Yes |
| 34 | Desktop | Text inputs use GPUI Kit's unstyled base `Input` and `Textarea` with Consort editor colors, inside Consort frames. | The styled kit input paints placeholders in `muted.foreground` (`text.secondary`) on every render. Placeholders must be `text.tertiary` | Yes |
| 35 | Desktop | Message Markdown is split into prose and fenced code. Prose renders in a selectable `TextView`. Code renders as `SelectableText` in a Consort code box, so each block has its own Copy code menu. No syntax highlighting yet. | A right click inside one `TextView` cannot tell a code block from prose. The kit builds without tree-sitter | Yes |
| 36 | Desktop | The timeline's top fade (24 px) always shows. The bottom fade (32 px) shows only while the reader is scrolled up. | At the live edge nothing is cut, and the Paper design has a 16 px gap above the composer | Yes |
| 37 | Desktop | The sidebar shows the Failed and Working glyphs too (mac-ext4 and house-lights in the mock), as design-system.md says. The Paper design shows none for those rows. A failed channel keeps its name in `text.secondary`. | The written rule wins over the mock-up. Failed is not the user's turn (decision 25) | Yes |
| 38 | Desktop | In the pressed Tasks button, "of 5 tasks" is `text.secondary`, not `text.tertiary` as in Paper. | `text.tertiary` never sits on `surface.selected` | Yes |
| 39 | Desktop | Resolve shows only for Ready for review and Not done only for Resolved, in task menus. | Only Review to Resolved is allowed for the user (decision 25) | Yes |
| 40 | Desktop | A click on a decision option answers at once. Write my own answer opens a text box with Send answer. Answer later closes the panel and leaves the decision pending. | The design shows no confirm step | Yes |
| 41 | Desktop | New task (header and Tasks panel) puts "Start a task to " in the composer. Search, attachments, voice input and threads on plain messages show a notice that they come in a later build. | No task dialog is designed, and the assistant starts tasks from messages | Yes |
| 42 | Desktop | Tasks panel sections list tasks newest first. After Back from a thread, that task's row is selected. | Paper sorts Working oldest first and Your turn newest first. One order is simpler | Yes |
| 43 | Desktop | Component sizes that `structure.json` does not name (settings label column, theme card, dialog fields, dots) are named constants in `consort-desktop/src/ui/sizes.rs`. View code has no other pixel literals. | AGENTS.md rule 5 | Yes |
| 44 | Desktop | `consort-desktop` takes `--mock`, `--screen <everything, sayso, tasks, thread, settings, workers, new-channel, add-worker, onboarding, menu, channel-menu>`, `--light`, `--dark` and `--theme <name>`. | Screenshots and reviews. While the display sleeps, GPUI draws only the first frame, so a screen must be set before the window opens | Yes |
| 45 | Client | The mock runs through the same derive rules (sidebar glyphs, Tasks panel groups, task meta lines) as the real reducers, and answers commands the way the hub would. | One set of rules, and the mock shows real behavior | Yes |
| 46 | Client | A paired client stores `client.json` (hub URL, client ID, name) and `client.key` (hex Ed25519 seed, mode 0600 on Unix) in `<config dir>/consort/`. `CONSORT_CONFIG_DIR` overrides the folder. | No keychain crate yet. The override lets tests and a second client run side by side | Yes |
| 47 | Client | A hub URL with no scheme gets `http` for localhost and 127.0.0.1, and `https` for any other host. | The dev hub listens on plain HTTP on 127.0.0.1:7600 | Yes |
| 48 | Client | Reconnects wait 0.5 s, doubling to 30 s, with 25 percent jitter either way. The client pings every 20 seconds. On reconnect it subscribes from its feed `seq`, and loads a snapshot only on `resync_required` or when it has none. | protocol.md asks for jittered backoff and catch-up from the last `seq` | Yes |
| 49 | Client | A message that the user sends shows at once as pending. When the link is down it stays pending and goes out on reconnect with the same `client_message_id`. | The hub returns the stored message for a repeated `client_message_id`, so a retry never doubles | Yes |
| 50 | Client | Approval buttons map to option kinds: Allow once to `allow_once`, Allow for this task to `allow_always`, Deny to `deny_once` or `deny_always`. | The harness options carry kinds (decision 15) | Yes |
| 51 | Client | The user's name in the sidebar is the OS user name with a capital letter, and the initials are its first two letters. | The hub has no user entity | Yes |
| 52 | Client | The composer hint "Runs on <worker> with <account>" uses the channel's first online preferred worker, else the first online worker that has the coordinator's account label. | The hub does not report where a coordinator runs yet | Yes |
| 53 | Client | Unread counts are the non-user timeline messages after the channel's read marker. Opening a channel sends `read.mark` with its newest message. | Read markers are shared by all clients | Yes |
| 54 | Client | Brief rows under a routine message (status glyph, line, channel) exist only in the mock. Real messages render as Markdown. | The hub has no structured task references in messages yet | Yes |
