# Design notes: dictation

These are the Paper designs for live dictation in the composer. The Paper file is `01M6342D512B1CKH0D29HMDN8V`, page "Redesign, Oct 30". The section header "Section: 10 Dictation" is at worldX 0, worldY 11548 (`NV7-0`). The artboards are in one row at worldY 11668, with a gap of 80 px. V1 is at worldX 0, V2 at 1520, V3 at 3040, V4 at 4560 and V5 at 5912. The row ends at worldY 12568, above the next row at 12688.

The behavior comes from how Claude Desktop does dictation. A click on the mic starts it. Words appear at the cursor as they are heard. They stay gray until dictation ends. The user does not accept them. Esc removes only the dictated words.

The owner approved this design and chose the engines in [../DICTATION-PLAN.md](../DICTATION-PLAN.md). The designs show the macOS case in English. There the live preview comes from a small model that writes no punctuation and no capitals. The final pass and the cleanup pass fix that when the user stops. Model names and sizes are the ones of the plan. The download size on Windows and Linux is smaller, because the live preview uses the final model there.

## Decisions the plan did not settle

- The gray text is `text.tertiary`, regular weight, not italic, as decided. It passes on `surface.card` at 4.67 to 1, which is above the 4.5 rule, and it reads at a glance in the screenshots. So the design does not use `text.secondary`. The placeholder has the same color. The two never show at the same time, because the placeholder shows only when the field is empty.
- The caret is `accent.text` and stays at the end of the heard words. The design draws it in the middle of a draft, so the user sees where the words go.
- The live mic button keeps the size of the rest button (28 px square), so the tool row does not move when dictation starts or ends. It has `accent.fill` at `opacity.tint` as its background, a 7 px stop mark and three level bars in `accent.text`. The stop mark says that a click stops. The bars show that the sound arrives. A tooltip is not drawn. The tooltip would say "Stop dictation".
- The field border is `accent.text` at 55 percent while the state is starting, listening or finishing. It returns to `border.strong` when dictation ends. The border is the one mark of the whole state, so the user sees it from the message text too.
- The right end of the tool row shows the state. "Runs on hub" gives way to "Esc cancels" while listening, to "Getting the speech model ready" while starting and to "Fixing the text" while finishing. The drop order is the existing one: this slot goes first, then the account name in the chips. Nothing wraps. In a 400 px panel the slot is gone and the account name still fits. In a 360 px window the account name is gone too.
- Starting looks like listening, because the audio is kept. The mic is live. A spinner (the working arc of the sidebar) and the text "Getting the speech model ready" say that the words will come late.
- Finishing puts the spinner in the mic slot and "Fixing the text" at the right. The words stay gray. Esc still cancels. There is no accept step, so Done only turns the words solid, puts the rest mic back and brings "Runs on hub" back.
- Cancelled shows no notice. Only the dictated words leave. The draft that the user typed stays, and the caret returns to where it was.
- A failure uses the corner notice styles of E3. An error has the `failed` icon, a title in UI semibold, the text in UI `text.secondary`, a secondary button and `close`. It stays until the user closes it. An information notice has an `info` icon in `status.working`. The design drew it as a circle with an "i", because the earlier designs do not show it.
- The mic gets a small `status.failed` dot when dictation cannot listen: no permission, no microphone, or a lost connection. The dot has a ring in the canvas color, so it reads on the tool row.
- An information notice with a button does not leave after 6 s. The design system says that an information notice is one line and leaves after 6 s. These notices have two sentences and an action. They stay until the user closes them or the state ends. The download notice closes when the download ends. The send notice closes when dictation finishes.
- The model notice covers the three models of macOS in English: Parakeet TDT v3 (483 MB, final text), Parakeet EOU 120M (222 MB, live preview) and Cleanup 1 by Spokenly (639 MB, cleanup). The total is 1.3 GB. On Windows and Linux the preview uses the final model, so the list has two models and the total is 1.1 GB. On macOS in other languages the preview model changes and the total is 1.8 GB. The design shows only the macOS English case.
- The download shows in a notice with one row for each model: its name, its size or progress, and a bar in `status.working` on `border.strong`. A finished model shows `status.done`. A model that waits shows an empty bar. "Dictation starts when all three are done." The mic is at rest and dim until the models are ready. "Cancel download" is the way out.
- A failed cleanup shows a quiet information notice: "Cleanup did not run" and "Consort kept your words as heard. You do not need to do anything." It has no button. The words are the text of the final pass and are solid. This follows decision 6 of the plan.
- Auto-stop ends like Stop. The state goes through Fixing the text and ends in Done. The only difference is an information notice: "Dictation stopped after 30 seconds of silence." It leaves after 6 s, as the owner asked on 2026-10-31. This replaces the quiet line in the tool row that V3 draws. Nothing is sent. The number in the line is the setting.
- The send notice adapts the text of Claude. The title is "Dictation is still finishing". The text is "Consort did not send your message. You can send again once it is done, or send now without the words still to come." The button is "Send now". The send key shows its pressed color.
- The cloud notice says "Lost the connection to Deepgram". Deepgram writes the final text at the end of each phrase, and the live preview is local. So the text says: "Deepgram writes the final text at the end of each phrase. Your words stay as this computer heard them. Try again, or finish on this device." The buttons are Try again and Finish on this device. The heard words stay gray, because dictation has not ended.
- The Dictation item is in the App group, after Notifications. The microphone, the shortcut and the engine are choices for this computer, not for the assistant. The Voice item (the `quote` icon) is in the Assistant group, after Memory, as the voice design says. The rail in V5 is the rail of R2, so it does not draw Voice.
- Engine is two radio rows. "On this device" has the badge "Recommended" (`accent.text` on `accent.fill` at `opacity.tint`), the line "Private and free. Your voice stays on this computer and works with no connection.", the model line "Parakeet TDT v3, 483 MB" with a `status.done` dot and "Downloaded", a quiet line under it ("The live preview on this Mac uses a second model, 222 MB."), and the button Remove. The quiet line shows on macOS only. When the model is not there, the button says "Download 483 MB". "Deepgram" says what it does and does not do: "Deepgram writes the final text only. The live preview stays on this computer." The button is Add key.
- "Fix the text after you stop" has two rows. The first is a switch, on by default, "Clean up the text": "Cleanup runs on this computer when you stop. If it fails, Consort keeps your words as heard." The second is a select, "Cleanup model", with the choices "Cleanup 1 by Spokenly, 639 MB" (the default) and "S1-mini by Superwhisper, 484 MB". The line says "The other choice is S1-mini by Superwhisper, 484 MB." The names are always written in full.
- "Stop when you stop talking" has one row, "Stop after silence", with a select: 15 seconds, 30 seconds (the default), 60 seconds and Never. The line says: "Works with both engines and runs on this computer. It never sends your message."
- The page is tight at 900 px, so Microphone and Shortcut share one group, and the gaps are smaller than in the first version.
- Language and Microphone are selects of 220 px. The Language line says that Parakeet TDT v3 hears 25 European languages. That claim is true for Parakeet TDT v3, so it stays. The preview and Cleanup 1 know fewer languages (the plan has the details), so the language list may need a note when the build has real data.
- The composer moves from `TextareaState` to `EditorState` for the gray range, because GPUI Kit 0.8.1 gives text decorations only to `EditorState`. See "Work in Consort", step 3, of the plan. The design needs this: gray text for a range in the middle of a draft (V2). The plan says to test the look, the context menu, IME, paste and undo first.
- Shortcut shows three key caps in mono (Control, Option, D) and a Change button. The line says that Esc cancels. Esc is not a setting.
- The task panel and the compact window use the same composer as the channel. V3 draws both with a live mic, so the narrow rule is visible.
- Copy follows the design system. It has sentence case, verbs on buttons and no all-caps. It has no middle dots, no arrows in button text and no em dashes. The text "Settings > Dictation" uses `>` in a sentence, as the design system does for "Settings > Memory".
- The timeline in V1 and V2 is the timeline of E1 with the error card removed, and one earlier user message added. The user answers the assistant who waits for their OK, so the draft in V2 reads as a real answer.

## Conflicts in the docs that the design shows

The build settled these. The Dictation section of the design system has the new text.

1. **The Dictation section of the design system describes system dictation.** It says that a click asks the system to start dictation and that an information notice shows a hint. DECISIONS 738 says the same, because the platform call needs `unsafe` code. The plan (decision 9) replaces this code with an engine that Consort runs. The section and DECISIONS 738 need a new text when the engine is built. This note does not change them.
2. **The mic is `component.composer_chip`, a square of 28 px.** The live mic keeps that size. It changes only its content and its tint.
3. **The info notice has no icon in the earlier designs.** The design system says it has an `info` icon. V4 draws it.

## Questions for the user

The plan answers the earlier questions about where the model runs (on the client, decision 1), about the correction pass (a local cleanup model, decision 5) and about the languages (decision 4). The user answered these on 2026-10-30.

1. The Deepgram key stays on this computer only. Each computer enters it once.
2. Send while listening stops dictation and fixes the text. Consort then holds the message and shows the same notice, with Send now.
3. A tap of the shortcut starts and stops. A hold of more than about 300 ms is push to talk. There is no setting.
4. "Finish on this device" does not show when the final model is not downloaded. The notice has only Try again.

The lead decided these.

5. Windows and Linux show the same notices as macOS, because the plan removes the "Windows key+H" hint. Only the model list differs.
6. The Auto-stopped message is a notice that leaves after 6 s.
