# Review fixes: write in my voice

These notes are for the merge into `docs/DECISIONS.md`. The review is `consort-wt/review-voice-report.md` (16 findings, at `8a7b5ce`). The orchestrator decided the fixes. Written on 2026-10-30. I checked each finding in the code before I changed it. Every finding was true, so none was skipped. Each fix has a test that fails without it.

## One line per finding

1. **Fixed.** The scan is new (`voice/scan.rs`, tests in `voice/scan_tests.rs`). It normalizes curly quotes and apostrophes, non-breaking and thin spaces, and case, with a map back to the original byte offsets. It finds every time, date, money and agreement format of the decision (a table test for each), and gives each match a value: minutes for a time, a month and a day (and a year when the text has one) for a date, cents and a currency for an amount, a canonical phrase for an agreement. It compares values with the values of the request, never substrings: `$50` against `$500`, `March 1` against `March 14`, `3:00 pm` against `13:00 pm`, `Deal` against `ideal` and `See you` against `see your` are all flagged now.
2. **Fixed.** The request is only the user's own words (`voice/card.rs`, `request_text` and `turn_user_text`). A task gets the user messages and typed answers of the coordinator turn that called `start_task`, stored in the new table `task_requests`, plus the user's replies in its thread; the brief and title count only for a task that the user created in a client. A coordinator gets the user messages and typed answers of its open turn, and the last 10 user messages of its channel only when the turn has a user message. `message_channel` text, lines that quote other text (`> ...`), briefs and tool output never count. A task with no user text has an empty request. Test: `the_request_is_only_the_users_own_words`.
3. **Fixed.** "Is a voice task" is the new table `voice_tasks` (schema 12), not `settings.task_id`. Learn again, Turn off and Reset call `stop_voice_tasks`: a running session ends, the task fails, and the waiting offer closes. An old voice task keeps its limits, and its `suggest_memory` fails (`policy_denied`) instead of going to Tutti. Test: `learn_again_stops_the_old_voice_task_and_it_keeps_its_limits`.
4. **Fixed.** `schema_v12.sql` makes `draft_pairs`, `voice_uses` and their indexes with `IF NOT EXISTS`, and adds `voice_tasks` and `task_requests`. Version 10 stays as it is ("never edit an old one"). Test: `a_hub_at_version_11_without_the_voice_tables_gets_them`.
5. **Fixed.** The hub owns `voice.md`: `memory_write` and `memory_delete` on it fail for every session with a message that points to `propose_voice_rule` and Settings > Voice. A learned rule goes through the new Tutti tool `propose_voice_rule { rule, context, pair_ids, replaces? }`; the hub checks 3 distinct edited pairs of that context and posts the offer itself. The coordinator prompt no longer says "decide for yourself" about `voice.md`. Tests: `sessions_cannot_write_voice_md_and_a_rule_needs_three_edits`, `writes_of_voice_md_keep_the_format_and_the_rules_of_the_user`, the integration test `a_session_that_can_send_gets_the_voice...`.
6. **Fixed.** The user's rules are `VoiceSettings.user_rules` (`{section, text}`). `VoiceGuide::with_user_rules` drops every `(you)` mark of a text and marks only these rules, in their own sections. So a forged mark is a learned rule, and a moved user rule stays in its section and in the scan. Tests: `user_rules_come_only_from_the_settings` (proto), `a_forged_user_mark_in_a_proposal_is_not_the_users`.
7. **Fixed.** The scan reads every string value of the arguments at any depth, except keys of recipients, IDs, URLs and timestamps. Edit stays on the top-level text fields. `outgoing_kind` knows `SCHEDULE`, `SCHEDULES`, `SCHEDULED` and `MESSAGE` with `CREATES`, `UPDATES` or `EDITS`. Tests: `every_string_of_the_arguments_is_scanned_except_addresses_and_ids`, `outgoing_tools_follow_the_hints_and_the_slug`.
8. **Fixed.** Each connector card stores `ask_rule`, the rule that made the hub ask. A late answer uses it and saves an allow only for "Ask once per task". Test: `a_late_answer_saves_an_allow_only_when_the_card_asked_once_per_task`.
9. **Fixed.** `DraftPair.final_bodies` keeps each text field alone, and the filter matches those (old pairs drop their `Subject:` line). A draft or send that ran with no card is stored as a sent-unchanged pair. Tests: `the_assistant_text_filter_matches_mail_with_a_subject`, `a_send_that_ran_without_a_card_is_the_assistants_text`.
10. **Fixed.** `placeholders` replaces `mailto:` addresses, addresses inside other text (`Email:dana@...`), written-out addresses (`dana [at] example [dot] com`), links with any scheme, and bare domains (`evil.com/pay`, `bit.ly/abc`, `example.com`), and drops `tel:`. `screened` applies it to `sources:`, `learned:` and `learned from:` too. Test: `screening_replaces_mailto_bare_domains_and_spelled_addresses`.
11. **Fixed.** Do it builds the guide at that moment: the stored proposal (or, for a rule offer, the current guide with the rule) gets the user's rules of now, then `fit_to_limit`. Test: `sessions_cannot_write_voice_md_and_a_rule_needs_three_edits` (a rule added while the offer waits stays).
12. **Fixed.** `ConnectorCard::review_hash` is a SHA-256 of the canonical arguments and flags. `ApprovalAnswer.checked_hash` must match it, or the hub answers `conflict`. The client keeps the tick per hash (`DraftCardView.review_hash`), so a new scan or another client's edit clears it. Tests: `the_tick_holds_only_for_the_flags_that_the_user_saw`, the integration test `with_the_voice_on_every_send_asks_and_a_draft_keeps_the_rule`, the desktop test `a_draft_card_keeps_allow_off_until_the_tick`.
13. **Fixed.** `ask_decision` with `offer` follows the normal gate in every turn; only the hub's own voice offers carry the `voice` mark. Voice offers follow the Tutti level: with Off, no `voice_edits` wake comes (the pairs wait) and `propose_voice_rule` fails. Tests: `an_offer_in_a_voice_turn_follows_the_normal_gate`, `with_proactivity_off_in_tutti_edits_wait_and_no_rule_is_offered`.
14. **Fixed.** Voice events get coordinator turns of their own (`turn_batch`), and a turn of voice events is the new `TurnKind::Voice`: only the voice tools, reading, `ask_decision`, posting and `no_reply_needed`. A send from "Try it" is not possible in such a turn; with the voice on, a send would ask anyway. Test: `voice_events_get_turns_of_their_own_with_the_voice_tools`.
15. **Fixed.** The maintenance purge removes every copy of a draft after 90 days: the pairs, the text of old draft and send cards, the arguments and output of those calls in session items, and the brief of an old voice task. The brief and the voice events quote drafts with placeholders. Test: `every_copy_of_a_draft_goes_after_90_days`.
16. **Fixed.** For a chat source without "Direct messages", the hub refuses a voice task read whose slug, channel ID or `types` or `query` names DMs or private channels, and removes such objects from results. A voice task's hub tools are only reading, `suggest_memory` and `submit_for_review`. Tests: `private_chats_stay_out_of_the_voice_task`, the integration test `the_voice_task_reads_only_the_chosen_sources...` (`post_update` refused).

Decision 1 of the orchestrator (sending in the voice always asks) is in `run_connector_tool` (`CardVoice::must_ask`), in VOICE-PLAN.md, ADR 0014 and the Approval line of Settings > Voice. Tests: `sends_in_the_voice_always_ask_and_drafts_keep_the_rule`, `with_the_voice_on_every_send_asks_and_a_draft_keeps_the_rule`.

## Decisions I made where the orchestrator left a choice open

- **"Voice on" for the send rule is the switch**, not "a guide exists". While the first guide is learned, sends ask too.
- **A forced card saves no allow.** A send in the voice, a call with flags, a proactive turn and a draft task all ask every time, so allowing such a card never lets a later call skip its card.
- **The review hash covers the arguments and the flags**, not the flags alone. An edit that keeps the same flags but changes other text still clears the tick, because the user checked that text.
- **Old voice tasks fail, they are not deleted.** The task fails first with the reason ("A new voice task replaced this one.", "The voice was turned off.", "The voice was reset."), then its session ends, and its update wakes Tutti. Their thread stays for the user. A retried old task keeps its mark and its limits. Because Reset now wakes Tutti, the integration test `try_it_writes_a_sample...` takes the turn on whichever coordinator session the hub uses after Reset.
- **The guide offer from Learn is not gated by the proactivity level.** It answers the user's own click. Only offers from edits (`propose_voice_rule`) follow the level.
- **Never about this on a rule offer turns off "Your edits to drafts"**; on the guide offer it still turns the voice off.
- **`propose_voice_rule` adds one rule** to the section of the event's context (`core` is the Core section), and can replace one learned rule. It cannot touch the user's rules or hard rules. A rule that the user asks for in chat goes to Settings > Voice; the prompt says so.
- **The user's rules at upgrade**: at the first start after schema 12, the `(you)` rules of `voice.md` become `user_rules` once (`voice_user_rules_adopted` in `meta`). `memory.restore` and `memory.move` of `voice.md` by the user take the note's marks again. Reset clears the list.
- **`$`, dollar words and `¥` match any currency of their group** (USD, CAD, AUD and others; JPY and CNY). Two different codes never match. An amount with no currency matches any currency of the same value.
- **A date without a year matches the same day in any year.** A numeric date that can be read both ways (`3/4`) has both values.
- **`sat` and `sun` count as weekdays** only next to a date sign (`Sat.`, `on Sun`, `Sat 14`), because they are also English words. Single-letter scales (`k`, `m`) count only right after the digits.
- **Keys that the scan skips**: recipients (`to`, `cc`, `bcc`, `from`, `recipient*`, `to_*`), `channel`, `user`, IDs (`id`, `*_id`), URLs (`url`, `*_url`, `link`), timestamps (`ts`, `*_ts`, `*_at`), and Slack's `type` and `style`. A scheduled send time (`post_at`) is a setting, not text in the user's name.
- **A coordinator's request includes recent channel messages only in a turn with a user message.** A turn that a decision answer or a task update started has only its own user text.

## What is left

- **Slack `text` with `blocks`.** The scan reads `blocks`, and its flags show on the card, but Edit changes only the top-level `text`. When both are set, Slack shows `blocks`, so an Edit of `text` may not show. The decision kept Edit on the editable text fields.
- **Mail "sent only".** The brief tells the voice task to read only sent mail, but the hub does not refuse a Gmail read of the inbox: no slug or argument says reliably which folder a read touches.
- **Copies outside the purge.** The model's own messages and summaries can quote a draft; the hub does not search them. The events of the last coordinator turn stay in its `coordinators` row until the next turn.
- **The harness mode of a voice turn** is the session's mode. Only the hub tools are limited. A stricter mode would make "Try it" fail on harnesses that cannot change mode in a session.
- **Screenshots.** No screen is new. The Approval line on the Settings > Voice off page has new text, and `docs/screenshots/phase4c-voice-off-dark.png` still shows the old line.
